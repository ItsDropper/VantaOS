# Desktop UI system

VantaOS renders its desktop directly into the framebuffer. Because it does not yet have a widget toolkit, the rendering helpers and input hitboxes are an application-level contract: visual changes must update the matching input geometry in the same change.

## Visual rules

- Use semantic colors from `include/desktop_theme.h` for shared surfaces, text, borders, and accents.
- Use `graphics_draw_window_frame` for application window chrome. Apps that expose minimize/maximize/close controls must pass `show_window_controls = 1` and keep those hitboxes aligned with the rendered 46-pixel titlebar. Apps without those behaviors pass `0` and render only Close.
- Prefer a quiet desktop background, a small number of useful shortcuts, and one restrained accent. Decorative status indicators are not allowed unless they report real state and have a defined action.
- Group related controls with spacing and alignment before adding extra borders. Keep labels short and consistent; reserve high-contrast accent colors for selection and actionable state.
- Terminal output must remain readable at the framebuffer's current fixed bitmap-font size. The visible-line calculation and cursor position must use the same line-height value.

These rules follow the general principles in [Microsoft Fluent 2 layout guidance](https://fluent2.microsoft.design/layout), [Fluent 2 accessibility guidance](https://fluent2.microsoft.design/accessibility), and [Nielsen Norman Group's usability heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/): consistent spacing and hierarchy, adequate contrast, predictable controls, and visible system state.

## Rendering and input ownership

- `kernel/graphics/graphics_ui.c` owns shared desktop chrome and the software-rendered desktop surface.
- `kernel/graphics/graphics_input.c` owns pointer hit-testing for desktop shortcuts and global window controls.
- `os/desktop/file_explorer.c` owns Explorer navigation and list rendering.
- `os/desktop/desktop.c` owns Terminal window composition, while `os/terminal/terminal.c` owns terminal history and cursor state.
- `include/desktop_theme.h` defines shared semantic color tokens.

The current implementation is still a direct framebuffer renderer rather than a general-purpose compositor or widget toolkit. Keep the drawing and hitbox changes paired, and validate the result by inspecting the screenshot generated by the QEMU workflow.

## Process model status

The desktop, Terminal, and Files currently have kernel process-table entries. That is not the same as running each app as a protected ring-3 user process: the GUI is still rendered and hit-tested by kernel-side code, and the Files process is currently a persistent kernel-side lifecycle placeholder. The user-mode ELF loader and syscall ABI exist, but a proper user-space GUI application model still needs a window-server/event IPC contract before moving these apps out of the kernel. Do not describe these GUI apps as isolated user-mode programs until that work is implemented and tested.
